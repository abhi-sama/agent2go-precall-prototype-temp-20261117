# Astryx migration: the foundation

Read this before revamping a page. Wave 1 put the whole app on [Astryx](https://github.com/meta/astryx)
(`@astryxdesign/core` 0.7.13) without redesigning feature pages. Every page already follows the chosen theme and colour
scheme through token aliases; wave 2 replaces each page's markup with Astryx components.

Use the CLI as the API reference and never guess props: `pnpm exec astryx component <Name> --dense`,
`pnpm exec astryx search "<query>"`, `pnpm exec astryx docs tokens`. Run `npx modern-web-guidance@latest search "<task>"`
before HTML/CSS/client-JS changes and `npx modern-web-guidance@latest legacy-scan src` on what you touch.

## How theming works

| Piece | Where | What it does |
| --- | --- | --- |
| Theme packages | `package.json`, `src/astryx-themes.ts` (generated by `astryx theme add`; do not edit) | All seven stable themes: neutral (default), butter, chocolate, matcha, stone, gothic (dark only), y2k. Built CSS + fonts. |
| Theme list for app code | `src/lib/appearance/themes.ts` | Slugs, labels, `DARK_ONLY_THEMES`. A unit test keeps it equal to the generated module. |
| Root `<Theme>` | `AppearanceProvider` (`src/lib/appearance/appearance-provider.tsx`), mounted in `src/app/layout.tsx` | Renders `<Theme theme mode>` around the whole app plus `<LinkProvider component={NextLink}>`, so Astryx links navigate client-side. |
| No flash | `APPEARANCE_BOOT_SCRIPT` (top of `<body>`) and `THEME_ROOT_SCRIPT` (first child of the Theme wrapper) | Before first paint: writes `data-astryx-theme`, `data-color-scheme`, `.dark` and `data-density` on `<html>` and copies the theme onto the server-rendered Theme wrapper. Hydration reads the same value, so nothing mismatches. |
| Colour scheme | `globals.css` | `:root { color-scheme: light dark }` follows the device. `<html data-color-scheme="light\|dark">` pins it (MWG dark-mode-toggle). The `dark:` variant follows the same rule, not a JS-only class. |
| Persistence | localStorage | `a2g.appearance` (this person's choice; scheme and density are also saved to their account through `setAppearance`), `a2g.themes` (`{ userId: theme }`, device-local), `a2g.device-appearance` (the look last shown on this device, used before sign-in). |
| Cascade layers | `src/app/layers.css` (imported first) | `reset, theme, base, astryx-base, astryx-theme, components, utilities`. Tailwind utilities win over Astryx defaults; Tailwind preflight sits below Astryx. |

The picker is `ThemePicker` (`src/components/shell/theme-picker.tsx`): an Astryx Selector for the theme, a
SegmentedControl for System / Light / Dark (locked to dark for gothic) and one for density. It lives in the
`AppearanceSettings` popover in the shell header and on `/login`. Read the current look with `useAppearance()`.

## Token aliases (legacy utilities keep working)

`globals.css` maps every legacy token to an Astryx token on `:where(:root, [data-astryx-theme])`, so `bg-card`,
`text-muted-foreground`, `border-border`, `bg-primary`, `shadow-card`, `rounded-xl`, the chart and map colours all follow
the theme. Examples: `--background` -> `--color-background-body`, `--card` -> `--color-background-card`,
`--primary` -> `--color-accent`, `--muted-foreground` -> `--color-text-secondary`, `--border` -> `--color-border`,
`--chart-1..6` -> `--color-data-categorical-*`, `--radius` -> `--radius-container`. `fact` / `ai` / `suggest` are mixed
from data-viz hues into each theme's text and card colours, so they stay legible in every theme.

Renamed to avoid a clash with Astryx tokens: `--duration-fast` / `--duration-slow` are now `--a2g-duration-fast` /
`--a2g-duration-slow`. Do not define app tokens named `--color-*`, `--spacing-*`, `--radius-*`, `--font-*`, `--text-*`,
`--shadow-*`, `--duration-*` or `--ease-*` (Astryx owns those namespaces).

## Charts, maps and 3D

Canvas and WebGL cannot read CSS variables. Use `resolveCssColor("--token", fallback)` (`src/lib/css-color.ts`): it
resolves `light-dark()` and translucent tokens inside the themed page and returns the opaque hex a person sees. Put
`useThemeSignature()` (`src/hooks/use-document-theme.ts`) in the effect or memo dependencies so colours are re-read when
the theme or scheme changes (see `echart.tsx`, `bar-field.tsx`, `territory-map.tsx`, `heatmap-panel.tsx`).

## Shell conventions

- `components/shell/app-shell.tsx` is Astryx `AppShell` (`height="auto"`, window scrolls) + `TopNav` + `SideNav`.
  Navigation and access stay in `persona-config.ts`; do not hard-code routes elsewhere.
- Below `xl` (1280px) the SideNav moves into the Astryx mobile drawer (portrait iPads); the header toggle is
  `data-testid="sidebar-menu"` and the drawer is `getByRole("dialog", { name: "Navigation" })`.
- AppShell renders the skip link and the `main` landmark. Pages start with their own `h1` and must not add `<main>`.
- Touch first: `globals.css` lifts every control to 44x44 under `(pointer: coarse)` and keeps fields at 16px on touch.

## Rules for wave 2

1. Import each component from its own entry (`@astryxdesign/core/Button`), never the package root.
2. Style with component props first, then token-backed Tailwind utilities. No raw hex or px; never override Astryx tokens on `:root`.
3. Dense data in `Table` / `List`, not lists of Cards. Status messages in `Banner`; transient feedback in Toast.
4. When a page no longer uses a `components/ui/*` file, delete the adapter once nothing imports it.
5. Check every page in at least neutral light, neutral dark and gothic, at 1024x1366, 1366x1024 and a desktop width.
   `e2e/support/appearance.ts` has `LOOKS`, `KEY_LOOKS` and `seedLook` for specs.
6. Visual baselines (`e2e/__visual__`) were removed with the old warm/clinical looks; regenerate with
   `pnpm test:visual:update` once the wave-2 pages land.

Every old element, wrapper and icon, with its Astryx replacement or the reason it was kept, is listed in [astryx-inventory.md](./astryx-inventory.md). Transient feedback uses `useAppToast()` (`components/state/use-app-toast.tsx`), a thin wrapper over Astryx `useToast` that keeps the `toast.success(title, { description })` call shape.
