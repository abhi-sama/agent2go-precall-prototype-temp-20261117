# Ask the agent suggests preferences it noticed, and saves one only on a click

Option B of ADR 0022. After an answer, Ask the agent may offer **one** preference it noticed in the conversation ("You asked for the last 90 days 3 times. Remember: 'Default to the last 90 days'?") on a card with **Remember** and **Dismiss**. Remember saves it through the path of ADR 0022 (the BE guard decides again); Dismiss records the suggestion so it is not offered again. The person can also ask outright ("what have you noticed about how I work?"). Nothing is saved without the click.

It is still memory of how a person likes to work, never data: a suggestion is never a name, record id, call detail or figure, and the figures behind an answer always come fresh from RLS-scoped SQL (ADR 0003). No background or cross-user extraction; no CopilotKit cloud (ADR 0018); no AWS AgentCore Memory (floci only stubs it, and its automatic extraction could store record-level facts).

## Decisions

**Detection is code, not the model.** `msl_agent/memory_suggest.py` reads only what the person typed in this conversation and counts it with a small closed set of detectors: the same date range (`last 90 days`, `30-day`), tables or charts, a number of bullets, a request for shorter answers, and a therapeutic area from a closed list (a free-text "focus on ..." could be a person or a record, so it is not detected). A habit needs three of the person's messages (a message counts once); two different values tie or lose to the most frequent; tables and charts equally often is no preference. Each one fills a **fixed template** ("Default to the last 90 days", "I prefer tables over charts", "Keep answers to 5 bullets", "Keep answers short", "Focus on oncology"), so a suggestion cannot carry text from a message, and the same guard as ADR 0022 checks it anyway. A message that is itself a `remember ...` command or a request to suggest is not evidence. Detection runs only on an ordinary answer: not on small talk, a form action, an evaluation run, or a write approval. Conversation-only is deliberate: a count across conversations would be a background job over history, which is out of scope.

**At most one per conversation, decided by the BE.** `startChatRun` asks the persisted event log (`chat_run_events` of this thread, under the caller's RLS, so only their own runs are visible) whether a `memory_suggestion` event already exists, and sends `memory_offered` with the run. The agent offers nothing automatically when it is true. The person asking outright ("suggest preferences", "what have you noticed about how I work?", "what should you remember about me") is the exception: that is a request, answered in code with no model call, with up to three cards, and it does not use up or respect the limit. The event log is working state (ADR 0007), so a thread whose log has been pruned could be offered again; the person's dismissals and saved items, which are the durable record, still apply.

**Dismissal storage: a hash, in the same table.** `dismissAgentMemorySuggestion(text)` stores `MEMX#<first 16 hex of sha256 of the lower-cased, single-spaced text>` with `createdAt` in the owner-keyed saved-views table, next to `MEM#` items (ADR 0022) and `PREF#` (ADR 0012); `SavedViews.list` filters the prefix. Only a text the guard accepts can be dismissed, so the mutation cannot be used to store anything else, and the store holds no preference words for something the person declined. The key function is the same in the BE and the agent (a shared test vector in `backend/agent_memory_suggestion_cases.json`). At most 50 are kept, oldest first out. `startChatRun` sends the keys with the run (`memory_dismissed`) and the agent leaves them out, along with anything already remembered (same text, any case). **Clear all** in the panel forgets the dismissals too, so a fresh start offers things afresh; deleting one remembered item does not record a dismissal.

**The path of a suggestion.** The agent emits one `CUSTOM` event `memory_suggestion {text, category, reason}` after `conversation_saved`, before the run finishes. It is answer evidence like the follow-ups: it passes the browser's event allow-list (ADR 0018), and `lib/chat/events.ts` re-checks it with the mirrored guard, the category list and a bounded, control-free reason before a card can show it, so a stored or tampered log cannot show a record fact. It cannot start a write: the browser's write tool (ADR 0020) is not involved. **Remember** calls `saveAgentMemory` for exactly the text on the card, and the BE guard, owner scoping and cap of ADR 0022 apply; **Dismiss** calls the mutation above. Both are the caller's own (the verified identity, ADR 0002); no argument names an owner. A card keeps what was decided in memory for the visit, so one that remounts does not offer it twice; a reopened conversation (ADR 0021) is rebuilt from saved turns and shows no card.

**Aggregate-only personas follow the same rule.** The guard and detectors do not depend on persona; an Executive gets the same closed templates, and a suggestion adds no access.

**Mirrors.** The mock adapter runs a TypeScript mirror of the detectors (`lib/data/memory-suggest.ts`) with its own dismissal store; both ends run `backend/agent_memory_suggestion_cases.json`, as the guard does with `agent_memory_guard_cases.json`.

## The card

The provenance `Suggestion` frame (dashed outline, lightbulb, the word "Suggestion"), titled "Remember this?", with the reason, the exact text, a sentence that it is about how the person works and nothing is saved without a click, and two buttons (44pt targets on touch). When one is chosen the buttons give way to a result line that takes focus (the clicked button has gone, so focus would otherwise fall to the page behind); a failed save or dismissal shows an alert and leaves both buttons.

## Not in this change

Counting across conversations or in the background, editing a suggestion before saving it, and recording a dismissal when a remembered item is deleted. The deployed IAM for the saved-views table is part of the AWS infrastructure work (ticket #24): the BE Lambda's role on it already needs `dynamodb:DeleteItem` for ADR 0022, and writes and queries the `MEMX#` items the same way.

## Testing

- `backend/agent/tests/test_memory_suggest.py`: the shared detector cases, the guard on every template, key parity, what is remembered or dismissed is not offered, one automatic offer after the answer and none when `memory_offered`, none on small talk or an evaluation run, asking outright (no model, limit ignored, nothing noticed), and the invocation's bounds.
- `backend/lambdas/api/tests/test_agent_memory.py`: key parity with the agent, a dismissal stores a hash and no words, owner privacy, only a preference can be dismissed, the cap, clear-all forgets dismissals, dismissals are not saved views or prompt items, a store that is down, the run's offered check (RLS-scoped SQL for this thread) and what the worker forwards. `tests/api/test_agent_memory.py` proves the mutation through AppSync on the local stack.
- `frontend/src/lib/data/memory-suggest.test.ts`, `agent-memory-suggest.test.ts`, `lib/chat/events.test.ts`, `run-stream.test.ts`: the mirrored detectors on the shared cases, the mock's dismissals and chat flow, the browser's re-check of a card, the allow-list, and the AppSync operation with no owner.
- `frontend/e2e/agent-memory-suggestions.spec.ts` on the iPad and MacBook projects: two asks offer nothing, the third offers one, nothing saved before the click, Remember and Dismiss, once per conversation, dismissed and remembered ones not offered again, clear-all offering afresh, asking outright, keyboard use, touch size and focus. The chat visual baselines do not change: the card appears only after a repeated ask.
