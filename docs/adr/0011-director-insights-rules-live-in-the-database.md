# Director insight rules (themes, emerging-topic thresholds, load status) live in the database

The Director insight fields (`topicHeatmap`, `questionAnalytics`, `emergingTopics`, `directorDrilldown`, `directorExceptions`, `territorySummaryEvidence`) are BE Lambda fields on the approved path (ADR 0001).
They are gated like the team overview (`team.overview.read`, ADR 0008) and every query runs under the caller's RLS scope (ADR 0003), so a Director only ever reads approved descendant territories and the records inside them.
MSLs and Executives are refused; Executives get their aggregate-only equivalents in #13.

## Decisions

- **One definition of a theme and of "emerging", in SQL.**
  `app.theme_of(text)` groups a free-text answer into a derived theme (a transparent keyword baseline, first match wins).
  `app.emerging_thresholds()` and `app.emerging_status(...)` are the explicit rule, and both the dashboard (Lambda) and the agent (chat and summaries) call them.
  A topic is judged on its share of free-text responses, comparing the requested window with the equal window before it.
  It is EMERGING when both windows have at least 30 free-text responses, the topic has at least 10 in the latest one, its share rose by at least 2 percentage points, and the new share is at least 1.5 times the old one (or the topic had none).
  DECLINING is the mirror image, INSUFFICIENT_SAMPLE is returned for a small window, anything else is STABLE.
  The numbers and the rule sentence travel with every result so the screen states the threshold it used.
  Nothing in the rule, the response or the screen says why a topic changed.
- **Themes are derived, never source facts.** Cards, heatmap cells and summaries are labelled derived and cite the responses behind them (`uniq_rspns_id`, openable through the citation query).
  Heatmap shares are over the territory's free-text responses and the denominator is returned with each cell.
- **Question analytics never mixes questions.** Bars count distinct responses to one question, with distinct HCPs and one stated denominator.
  A follow-up is read against its parent only inside the same interaction; an orphan parent is reported as not in the catalog, not hidden.
- **Drill-down stops where permission stops.** Region, territory and HCP levels list only what RLS lets the caller read.
  An out-of-scope or nonexistent region, territory or HCP gets the same `Forbidden`, and an HCP opens the existing `hcpTimeline` for interaction and response detail.
- **Exceptions are rules over in-scope records, plus one narrow door.**
  Missing joins (parent question not in the catalog, call-feed team members that match no roster member), unresolved identities (roster rows sharing a login, HCP identifiers with no canonical HCP), duplicate response keys, catalog-vs-response status differences and months with no recorded call are computed over the caller's own rows.
  Stale and failed loads come from `app.source_load_status()`, a SECURITY DEFINER function that returns only source name, state and timestamps (never row counts or error text) to callers holding `team.overview.read` or `admin.manage`, because `ingestion_runs` stays administrator-only.
  A finding says a join or load is missing, never that a person did something wrong.
- **AI summaries are written from computed evidence, through the approved path.**
  `territorySummaryEvidence` returns the source figures and cited responses per territory.
  The summary text is generated by the agent in a chat run started with a screen context (`intent: TERRITORY_SUMMARY`), so it travels FE AppSync -> BE Lambda -> AgentCore agent -> Bedrock, streams through the polled event log (ADR 0007), is labelled AI and cites its responses.
  The agent's `get_topic_trends` tool calls the same SQL functions, returns counts only (the model may not compute shares), and the number check flags any figure the answer did not copy from a tool result.
  Only callers with `team.overview.read` or `admin.manage` may start a summary run, decided in code in `startChatRun`.
- **Screen context is a default, not authority.** `startChatRun` accepts an optional context (view, territory, question, dates, intent) that is validated by pattern in the BE and again in the agent.
  It supplies default tool arguments and picks the task; every tool still reads under the caller's RLS session, so a context naming another region's territory reads nothing.
  The agent also gained `get_question_breakdown` for "how did HCPs answer Q-0013" questions.

## Consequences

- Changing a keyword or a threshold is a migration, and the dashboard, the chat and the summaries change together.
- The heatmap and trend queries classify free text in SQL on each request; at the medium seed (60k responses) they run in well under a second under a Director's scope.
- Follow-ups: governed (versioned) threshold configuration belongs with the metric-definition catalogue (#18); Executive aggregate variants with small-group suppression are #13/#14; a semantic (embedding) theme model could replace the keyword baseline without changing the contract.
